# タスク：高校の文化祭用「うちみくじ」サイトを作成する

## 目的
高校の文化祭で来場者がスマートフォンから利用できる、おみくじサイトを作成する。

GitHub Pagesで公開するため、GitHub Pagesで動作しない機能は実装しない。

# 1. 動作概要

サイトは以下の3段階で動作する。

## 画面1：タイトル画面
- 「うちみくじ」というタイトルを表示する。
- おみくじを引くボタンを表示する。
- ボタンを押すと、おみくじの演出画面へ移行する。

## 画面2：おみくじの演出
- おみくじを引いたことが分かる演出を表示する。
- CSSアニメーションなどを使い、スマートフォンでも快適に動作する演出にする。
- 演出が終了すると、おみくじ結果画面へ移行する。
- 演出中にボタンを連続して押しても、結果が重複して表示されないようにする。

## 画面3：おみくじ結果
- 中央に、指定された画像の中からランダムに選ばれた1枚を表示する。
- 画像の下に、その画像に対応するおみくじの文章を表示する。
- 文章の下に「もう一度引く」ボタンを表示する。
- 「もう一度引く」を押すと、演出画面を経由して新しい結果を表示する。

# 2. おみくじデータ

おみくじの画像と文章は、JavaScriptのデータとして管理する。

各おみくじは、次の情報を持つ。

- 画像のパス
- おみくじの文章
- 必要であれば、おみくじの種類や名前

おみくじの結果は、登録されたデータからランダムに1つ選ぶ。

画像と文章の組み合わせがずれないようにする。

同じ結果が連続して出ることは許可する。

画像の登録数や結果の種類を、後から簡単に変更できる構成にする。

# 3. スマートフォン対応

- スマートフォンでの利用を最優先にする。
- 画面幅に応じてレイアウトが変化するようにする。
- 横スクロールが発生しないようにする。
- ボタンはスマートフォンで押しやすい大きさにする。
- 画像は画面からはみ出さないように表示する。
- 文字は読みやすい大きさにする。
- タイトル画面、演出画面、結果画面は同じページ内で切り替える。

# 4. 技術的な制限

- HTML、CSS、JavaScriptを使用する。
- GitHub Pagesで公開できる静的サイトにする。
- サーバー、データベース、バックエンドAPIを使用しない。
- ログイン機能や個人情報の保存機能は作成しない。
- 外部サービスへの依存を最小限にする。
- GitHub Pagesで公開する際に、画像やCSS、JavaScriptのパスが正しく動作するようにする。
- 絶対パスではなく、GitHub Pagesのプロジェクトサイトでも動作する相対パスを使用する。
- 既存のプロジェクト構成を確認してから編集する。

# 5. 画像について

まず、プロジェクト内におみくじ用の画像が存在するか確認する。

画像がある場合は、その画像を利用する。

画像がない場合は、画像を後から配置できる構成を作り、仮の画像または簡単な代替表示を用意する。

画像ファイルが存在しないのに、実在する画像を使用したと報告しない。

# 6. デザイン

文化祭で利用するため、親しみやすく、明るい雰囲気のデザインにする。

- タイトル画面は「うちみくじ」の文字が目立つようにする。
- おみくじを引くボタンは、画面の中央付近に配置する。
- 演出画面は、結果が出るまでの期待感を持たせる。
- 結果画面では、おみくじの画像を中央に配置する。
- 結果の文章は画像の下に配置する。
- 「もう一度引く」ボタンは文章の下に配置する。

# 7. テスト条件

以下の動作を確認できるようにする。

1. タイトル画面が正常に表示される。
2. おみくじを引くボタンを押すと演出画面に移行する。
3. 演出終了後に結果画面が表示される。
4. 画像と文章が正しく対応している。
5. もう一度引くボタンで新しい抽選を実行できる。
6. スマートフォン相当の画面幅でも表示が崩れない。
7. ブラウザのコンソールにエラーが出ない。
8. GitHub Pagesで使用できない機能が含まれていない。

# 8. 実装の進め方

1. 既存のファイル構成を確認する。
2. 変更対象のファイルと実装方針を説明する。
3. 必要なコードを実装する。
4. 変更したファイルを報告する。
5. テストが未実施の場合は、そのことを明記する。

指定された機能以外は変更しない。
既存のファイルを削除しない。
既存のプロジェクト構成をできるだけ維持する。
